# HISTORY

**언제 무엇을 했고, 무엇이 나중에 뒤집혔는지의 누적 기록이다.** 실행 시점마다 한 항목씩
쌓는다. 지난 항목은 **고치지 않는다** — 나중에 틀린 것으로 드러나면 지우는 것이 아니라
아래 「뒤집힌 것」에 한 줄을 더한다.

다른 문서와의 차이는 이렇다.

| | 무엇 | 고치나 |
| --- | --- | --- |
| **이 문서** | 시점의 누적. 연표 · 각 라운드에 무엇을 돌렸나 · 무엇이 뒤집혔나 | **안 고친다. 덧붙인다** |
| `스윕_결과.md` · `2차_스윕_결과.md` · `에폭_결과.md` · `베이스라인_기록.md` | 그 시점에 나온 **결과 본문** | 안 고친다 |

| `PLAN.md` · `TODO.md` | 앞으로 할 일 (git 추적 안 함) | 계속 고친다 |

## 각 라운드에 무엇을 돌렸나

**설정 파일(JSON) 하나가 실험 하나다.** `configs/_base.json`이 기준 조건이고, 나머지는
그것을 물려받아(`extends`) **바뀌는 칸만 적는다.** 파일 하나가 곧 그 실험의 차이 목록이다.

```json
{ "extends": "_base.json", "name": "lora-dora", "peft": { "use_dora": true } }
```

이 파일이 말하는 것은 **"기준 조건과 전부 같고 DoRA 하나만 켰다"**이다. 비교 실험이
전부 "다른 건 똑같이 두고 하나만 바꾼다"라 이렇게 한다 — 설정마다 학습률을 다 적어두면
한 곳을 고칠 때 나머지가 옛 값으로 남아 통제가 조용히 깨진다.

기준 조건(`_base.json`)은 이렇다.

```
모델     KORMo-Team/KORMo-10B-base
PEFT     LoRA r=32 · alpha=64 · dropout=0.05 · 7개 모듈 전체
학습     3에폭 · 학습률 2e-4 · 유효 배치 8 · 4K 문맥 · seed 42
정답     judgement -> labels -> impacts -> direct_impact (전체)
입력     역할 A 규칙서 전문 + 블록쌍
```

### 1차 (2026-08-11~12) — 70줄

| | 줄 | 무엇 |
| --- | ---: | --- |
| **다른 PEFT 방식** | **40** | 38종. DeLoRA만 3줄(seed 3개), 나머지 37종은 한 줄씩 |
| **LoRA 축** | **30** | LoRA는 붙는 것이 확인됐으니 그 위에서 흔든다 |

**다른 방식 40줄이 이 프로젝트의 1차 목표다.** KORMo는 `KORMoForCausalLM`이라는 자체
모델 클래스를 써서, 어떤 PEFT(원본 가중치를 얼려두고 작은 어댑터만 학습하는 방식)가
붙는지 **알려진 바가 없다.** `peft` 0.20.0이 지원하는 42종에서 LoRA(기준)와 인자 형태를
아예 모르는 것을 빼고 39종을 넣었고, DeLoRA가 유일하게 붕괴를 벗어나 seed 43·44를
뒤늦게 붙여 40줄이 됐다.

39종은 성격이 셋으로 갈린다. **갈라 두는 이유는 실패의 뜻이 다르기 때문이다.**

| 갈래 | 예 | 왜 갈라 두나 |
| --- | --- | --- |
| 구조를 가정하는 것 | IA3 · VeRA · LoHa · LoKr · OFT · TinyLoRA | 층의 모양을 전제하므로 **안 붙을 확률이 높다** |
| 처음 보는 것 | DeLoRA · RandLoRA · GraLoRA · UniLoRA · Peanut | **붙는지 자체가 정보다** |
| 프롬프트 계열 | Prompt Tuning · P-Tuning · Prefix Tuning · CPT | 어댑터가 아니라 **가상 토큰**을 앞에 붙인다 |

**터지는 것도 결과다.** 무엇이 KORMo에 못 붙는지를 그리는 것이 목적이다. 다만 "인자를
잘못 준 것"과 "진짜 안 붙는 것"은 다르므로 `cli.sweep --check`로 GPU를 쓰기 전에 한 번
거른다(`adamss`가 여기서 떨어져 표에 행이 없다 — 그래서 설계 68 + DeLoRA seed 2 +
기준 조건 1 − `adamss` 1 = 70줄이다).

**LoRA 축 30줄의 내역이다.**

| | 개수 | |
| --- | ---: | --- |
| 대조군 | 1 | 기준 조건 그대로 |
| 대조군 seed | 2 | seed 43 · 44 |
| rank | 4 | 8 · 16 · 64 · 128 (기준 32) |
| LoRA 변형 | 3 | DoRA · rsLoRA · PiSSA |
| 학습률 | 3 | 5e-5 · 1e-4 · 5e-4 (기준 2e-4) |
| **데이터 조건** | **15** | 아래 5조건 × seed 3개 |
| 조건 교차 | 2 | `no-impacts`×규칙서없음 · `sentence`×규칙서없음 |

데이터 조건 다섯은 기획서 3.3의 축 1(무엇을 학습시키나)·축 2(데이터 구성)다.

```
rules=false        규칙서 3,300자를 떼면?
target=no-impacts  중간 산출물 impacts 배열을 빼면?
target=sentence    최종 문장만 학습시키면?
negatives=drop     negative를 빼면 과대해석이 느나?
downsample=120     한 계열 쏠림(60%)을 줄이면?
```

**seed는 난수의 출발점일 뿐이고 나머지는 완전히 같다.** 홀드아웃이 37건이라 한 건이
2.7%p이므로, 두 조건이 10%p 차이 나도 진짜 차이인지 흔들림인지 seed 하나로는 말할 수
없다. **PEFT 방식에는 seed를 안 붙였다** — "붙나 안 붙나"가 사실상 예·아니오라서다.

### 2차 (2026-08-14~18) — 66줄

**조합을 새로 설계한 것이 아니다. 1차와 거의 같은 목록을 학습 데이터만 바꿔 다시 돌렸다.**

```
70 (1차) − 5 (진짜 안 붙는 것) + 1 (delora-sentence) = 66
```

**뺀 5개**는 로그의 실제 예외로 갈랐다 — `cartridge` · `cpt` · `poly` ·
`prefix-tuning` · `trainable-tokens`. 데이터를 바꿔도 안 붙는 것들이다(예: `poly`는
레코드마다 과제 번호를 요구하는데 우리 데이터에 그 칸이 없다).

**OOM 5개**(`boft`·`frod`·`ln-tuning`·`osf`·`randlora`)는 **도로 넣었다.** 방법 탓이
아니라 한 장에 둘씩 물린 탓으로 봤다. 결과적으로 `frod`만 맞았다.

**더한 1개** `delora-sentence`는 1차 표에 행이 없던 조합이다.

| | 1차 | 2차 |
| --- | ---: | ---: |
| 다른 PEFT 방식 | 40줄 (38종) | **36줄 (33종)** |
| LoRA 축 | 30줄 | **30줄** |

**LoRA 축 30줄은 1차와 완전히 같다.** 바뀐 것은 방식 쪽 개수뿐이다.

**"방법론 66가지"가 아니다.** 66줄 중 **30줄이 LoRA 하나**의 변주이고, 서로 다른 방식은
33종이며 그중 DeLoRA만 4줄(기본 · seed 43 · seed 44 · sentence)을 쓴다.

- 학습 데이터는 `data/20260814__annotate__v2.2-synth/`
  (train 1,655건 · holdout 37건 · 합성 원본 1,093건). 커밋 `93644eb`.

### 3차 (2026-08-18 저녁 ~ 08-19) — 6줄, 학습률 축

**1·2차에서 바닥에 깔려 있던 여섯이 「KORMo에 안 붙는 방법」인지 「학습률을 잘못 준
방법」인지를 가른다.** `fourierft` · `c3a` · `adalora` · `pvera` · `unilora` · `vera`다.

각 `-r2` 설정에서 **`learning_rate` 한 칸만** 2e-4 → 1e-2로 바꿨다. 근거는 08-18에 잰
`vera-lr1e-2` 한 건인데, 그것은 1차 데이터 위에서 돌아 형식을 배우자마자 전부 negative로
붕괴했다. **비어 있던 칸이 「높은 학습률 × 2차 데이터」다.**

| | lr 2e-4 (2차) | lr 1e-2 (3차) | 3차의 판정 분포 |
| --- | ---: | ---: | --- |
| c3a | AM1 10.8% | **91.9%** | `{'': 3, 'positive': 34}` |
| pvera | 8.1% | **70.3%** | `{'': 11, 'negative': 26}` |
| fourierft | 8.1% | **40.5%** | `{'': 22, 'positive': 15}` |
| adalora | 8.1% | **24.3%** | `{'': 28, 'positive': 4, 'negative': 5}` |
| vera | 2.7% | **13.5%** | `{'': 32, 'positive': 2, 'negative': 3}` |
| unilora | 10.8% | 10.8% | `{'': 33, 'positive': 4}` |

**여섯 중 다섯에서 형식을 배웠다. 그러나 아무도 `됨`에 못 갔다.** 2e-4에서는 말을 못
하고, 1e-2에서는 말은 하는데 한 마디만 반복한다. 넷이 쏠림 100%다.

**`c3a`의 교사일치 70.3%를 실력으로 읽으면 안 된다.** 홀드아웃이 positive 26 ·
negative 11이라 **무조건 positive면 정확히 70.3%**이고, 판정 분포가 `positive: 34`라
그 이론값 그대로다. `됨`을 못 받았는데 교사일치만 DeLoRA 다음으로 높아 보이는 칸이라
**인용할 때 분포를 반드시 같이 놓는다.**

**붕괴 방향이 데이터를 따라 뒤집혔다 — 같은 학습률에서다.**

```
1차 데이터(negative 45.9%)  + 1e-2  ->  {'': 3, 'negative': 34}   교사일치 27.0% (이론값 29.7%)
2차 데이터(negative 15.95%) + 1e-2  ->  {'': 3, 'positive': 34}   교사일치 70.3% (이론값 70.3%)
```

형식을 배우자마자 **그 데이터에서 제일 흔한 답**으로 직행한다. 「한 축을 밀면 반대쪽이
무너진다」의 세 번째 사례다.

**데이터가 붕괴를 강요하는 것은 아니다** — 같은 2차 데이터에서 `delora-r2`는
`{'': 1, 'positive': 27, 'negative': 9}`로 제대로 가른다.

**`vera`는 데이터를 늘리자 거꾸로 갔다.** 같은 1e-2에서 1차 데이터 AM1 91.9%,
2차 데이터 13.5%다. 다른 축은 같고 데이터만 다르다. `lr_scheduler_type`이 설정에 없어
기본값 `linear`가 걸리는데, 데이터가 3배면 스텝도 3배라 **1e-2로 3배 오래 미는 셈**이다.
확인하려면 스케줄러를 바꿔 다시 돌려야 하므로 조건이 하나 더 풀린다.

### 두 라운드 사이에 바뀐 것 — **학습 데이터 하나뿐이다**

```
1차   562건    negative 45.9%
2차   1,655건  negative 15.95%   (합성 1,093건을 더함)
```

방식도 학습률도 rank도 seed도 에폭(3)도 그대로다. **그래서 "붕괴 26개가 살아난 것은
데이터 때문"이라고 말할 수 있다** — 다른 것이 안 바뀌었으니 해석의 여지가 좁다.

**설정을 `-r2` 이름으로 새로 만든 이유**는 `cli/sweep.py`가 `runs/<이름>/eval/
summary.json`이 있으면 "이미 끝난 것"으로 큐에서 빼기 때문이다. 1차와 같은 이름을 쓰면
아무것도 안 돌아가고, `--redo`를 붙이면 1차의 어댑터와 기록을 덮어쓴다.
