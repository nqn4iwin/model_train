# frod 를 2차run 에 넣고 싶어지면

2026-08-21에 씀. **주말에 혼자 판단해야 할 때를 위한 문서다.**

`frod`(FROD)는 2차run 후보 9종 중 하나인데 **이번 판에서 뺐다.** 다시 넣고 싶어지면
여기를 따라간다. **결론부터: 재채점만 넣는 것은 되고, 학습까지 넣는 것은 이번 주말엔
안 된다.**

## frod 가 무엇이고 왜 뺐나

`peft` 42종 중 하나다. 성적은 좋다 -- 1차run(1,655건)에서 **교사일치 83.8% · AM 평균
100.0%** 로 `됨` 판정을 받았고, prerun 에서는 자리가 모자라 못 돌았다가 한 장을 혼자
줬을 때만 살아난 이력이 있다(`docs/HISTORY.md` 2026-08-12).

**뺀 이유는 성적이 아니라 채점 속도다.**

| | frod-r2 | delora-r2 |
| --- | ---: | ---: |
| 학습 (1,655건) | 105분 | 87분 |
| **채점 (37건)** | **315분** | **9.9분** |
| 건당 채점 | **8.5분** | 16초 |

**학습은 비슷한데 채점이 32배다.** 그리고 `안 멈춘 것 0 · 잘린 것 0` 이므로
**모델이 지껄여서가 아니다** -- 출력은 깨끗하고 생성 자체가 느리다. 이 방식의 성질로
보인다.

홀드아웃이 37건에서 135건이 되면 그대로 3.65배가 붙는다.

```
frod 채점 (135건)   315분 x 135/37 = 1,150분 = 19.2시간   <- 한 장을 혼자 19시간 쓴다
```

**남은 37개를 다 합친 것(14.4시간)보다 길다.** 이것이 뺀 이유의 전부다.

## 두 가지 선택이 있고 값이 아주 다르다

| | 무엇 | 드는 시간 | 이번 주말에 되나 |
| --- | --- | ---: | --- |
| **A. 재채점만** | 이미 학습된 `frod-r2` 어댑터를 135건으로 다시 매긴다 | **19.2시간** (GPU 한 장) | **된다. 다만 빠듯하다** |
| B. 학습까지 | 조건 A·B 두 판을 3,178건으로 새로 학습하고 채점 | **45시간** (3.4h 학습 + 19.2h 채점) x 2판 | **안 된다** |

**B 를 권하지 않는 이유**는 계산이 안 맞아서다. 재채점 76개(11.9h) + 학습 28판(28.8h)이
이미 40.7시간이고, 금요일 저녁부터 월요일 오전까지가 약 64시간이라 **여유가 23시간**이다.
B 는 45시간이라 **그 안에 안 들어간다.** 넣으면 다른 것이 못 끝난다.

## A -- 재채점만 넣는 법

**한 줄이면 된다.**

```bash
cd /data1/yblee/repository/model_train && source .venv/bin/activate
echo "frod-r2" >> configs/run2-rescore.txt
```

그다음 **스윕이 내려간 상태에서** 이어 돌린다. `run2_resume.sh` 는 이미 끝난 것을
건너뛰므로 `frod-r2` 하나만 새로 돈다.

```bash
bash run2_resume.sh --status     # 먼저 현황을 본다
bash run2_resume.sh              # 살아 있으면 아무것도 안 하고 물러난다
```

### 돌기 전에 반드시 볼 것 둘

**1. 어댑터가 있나.** 없으면 재채점이 아니라 재학습이라 값이 완전히 달라진다.

```bash
ls -d runs/frod-r2/final
```

**2. 지금 남은 시간이 19.2시간보다 넉넉한가.** frod 는 **한 장을 혼자 19시간 쓴다.**
그동안 나머지 한 장만 다른 일을 하므로 **전체 진도가 절반이 된다.** 남은 학습이 많으면
frod 를 넣는 순간 월요일에 학습이 안 끝날 수 있다.

```bash
bash run2_resume.sh --status     # "안 됨" 이 몇 개인지 본다
```

남은 학습이 **8판(약 12시간) 이하일 때만** 넣는 것을 권한다.

### prerun 쪽 frod 는 어떻게 되나

`runs/frod/` 는 표에서 `못 돌림` 으로 잡힌다. 자리 부족으로 죽었다가 한 장을 혼자 줘서
되살린 이력이 있는데, **그 결과가 1건짜리 채점 찌꺼기로 남아 있어**(`runs/frod/eval/`,
`docs/TODO.md` 에 있는 항목) 정상 결과로 안 잡힌다. 어댑터가 남아 있는지부터 본다.

```bash
ls -d runs/frod/final
```

있으면 `configs/run2-rescore.txt` 에 `frod` 한 줄을 더 넣으면 되고, **19.2시간이 한 번
더 붙는다.** 없으면 재학습이라 이번 주말엔 접는다.

## B -- 학습까지 넣게 되면 (다음 판에서)

설정 두 개를 만든다. 다른 설정과 같은 자리에 넣고 **`peft` 칸만 다르다.**

```bash
cd /data1/yblee/repository/model_train
for C in A B; do
python - "$C" <<'PY'
import json, sys, io
c = sys.argv[1]
other = "B" if c == "A" else "A"
comp = "9.7" if c == "A" else "5.0"
kind = "복합(사슬 최종본)" if c == "A" else "단일(사슬 중간본)"
cfg = {
  "extends": "_base.json",
  "name": f"frod-run2{c}",
  "note": (f"2차run 조건 {c} · FROD · seed 42. 조건 {c}와 {other}는 3,178건 중 183건만 "
           f"다르다 -- {kind}이라 복합 비율이 {comp}%다. **채점이 아주 느리다** -- "
           f"1차run에서 37건에 315분(건당 8.5분)이라 135건이면 19.2시간이다. 지껄여서가 "
           f"아니라(안 멈춘 것 0 · 잘린 것 0) 생성 자체가 느리다. 성적은 좋다 -- "
           f"1차run 교사일치 83.8% · AM 100.0%. prerun에서는 자리가 모자라 못 돌았고 "
           f"한 장을 혼자 줬을 때만 살아났다. **한 장을 19시간 점유하므로 큐에 넣을 때 "
           f"다른 실험의 진도가 절반이 되는 것을 셈에 넣는다**"),
  "data": f"data/20260821__annotate__v2.2-run2{c}/train.jsonl",
  "peft": {"peft_type": "FROD",
           "target_modules": ["q_proj","k_proj","v_proj","o_proj",
                              "gate_proj","up_proj","down_proj"]},
}
io.open(f"configs/frod-run2{c}.json","w",encoding="utf-8",newline="\n").write(
    json.dumps(cfg, ensure_ascii=False, indent=2) + "\n")
print("만들었다: configs/frod-run2%s.json" % c)
PY
done
```

만든 뒤에 **설정이 실제로 만들어지는지부터 본다.** GPU 를 안 쓰고 몇 초다.

```bash
python -m cli.sweep --check --configs configs/frod-run2A.json configs/frod-run2B.json
```

통과하면 순서 파일 **맨 앞**에 넣는다. 긴 것부터 넣어야 나머지가 그것을 기다리지 않는다.

```bash
sed -i '1i configs/frod-run2A.json\nconfigs/frod-run2B.json' configs/run2-order.txt
```

## 넣을지 말지의 판단 재료

**넣을 이유.** 1차run 에서 AM 평균 100.0% 로 형식을 완벽하게 냈다. 9종 중 그런 것이
흔하지 않다. 그리고 prerun 에서 `못 돌림` 이었다가 1차run 에서 `됨` 이 된 쪽이라
**데이터가 늘면서 살아난 계열**이고, 3,178건에서 더 좋아질 여지가 있다.

**안 넣을 이유.** 건당 8.5분이면 **실전에서 쓸 수 있는 속도가 아니다.** 이 과제의
산출물은 문서 개정 해석인데, 조문 하나에 8.5분이면 사람이 읽는 것보다 느리다.
지도를 그리는 값은 있지만 **후보로 데려갈 값은 낮다.**

**그래서 이번 판에서는 재채점(A)까지만 하고, 학습은 다음 판으로 미루는 것을 권한다.**
재채점만 해두면 135건 자로 찍힌 점이 하나 생기므로, 다음에 판단할 재료가 남는다.

## 하면 안 되는 것

**`run2_start.sh` 를 다시 부르지 않는다.** 그것은 처음 띄우는 용도이고, 도는 중이면
물러나기는 하지만 이어 돌리는 장치(학습만 끝난 것을 채점만 붙이는 것)가 없다.
**끊긴 것을 이을 때는 언제나 `run2_resume.sh` 다.**

**`cli.sweep --all` 을 부르지 않는다.** `eval/summary.json` 이 없는 설정을 전부 "안
돌린 것" 으로 보고 **166개를 처음부터 다시 학습시킨다.**

**`--redo` 를 붙이지 않는다.** 이미 있는 어댑터와 기록을 덮어쓴다.
