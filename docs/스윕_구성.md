# 68개 조합이 어떻게 나온 것인가

`configs/` 아래 설정 파일 하나가 실험 하나다. `_base.json`은 기준 조건이라 세지 않고,
나머지 68개가 이 문서의 대상이다.

## 한 줄 요약

**PEFT 방법론 39 + LoRA 변형 3 + rank 4 + 학습률 3 + 구조화 조건 5 + 교차 2 + seed 12 = 68**

## 기준 조건 하나에서 한 칸씩만 바꾼다

모든 설정은 `_base.json`을 물려받고(`extends`) **바뀌는 칸만 적는다.** 파일 하나가 곧
그 실험의 차이 목록이다.

```json
{ "extends": "_base.json", "name": "lora-dora", "peft": { "use_dora": true } }
```

이렇게 하는 이유는 비교 실험이 전부 "다른 건 똑같이 두고 하나만 바꾼다"이기 때문이다.
설정 68개에 학습률을 68번 적어두면, 한 곳을 고칠 때 67곳이 옛 값으로 남아 통제가 조용히
깨진다.

기준 조건은 이렇다.

```
모델      KORMo-Team/KORMo-10B-base
데이터    학습 562건 (홀드아웃 37건은 채점용으로 뺌)
PEFT      LoRA r=32 · alpha=64 · dropout=0.05 · 7개 모듈 전체
학습      3에폭 · 학습률 2e-4 · 유효 배치 8 · 4K 문맥
정답      judgement -> labels -> impacts -> direct_impact (전체)
입력      역할 A 규칙서 전문 + 블록쌍
```

## 1. PEFT 방법론 39개

**이 프로젝트의 1차 목표가 여기다.** KORMo는 `KORMoForCausalLM`이라는 자체 모델 클래스를
쓰므로, 어떤 PEFT(parameter-efficient fine-tuning, 원본 가중치를 얼려두고 작은 어댑터만
학습하는 방식) 방법론이 붙는지 알려진 바가 없다.

`peft` 라이브러리 0.20.0이 지원하는 42종에서 LoRA(기준 조건)와 인자 형태를 아예 모르는
것을 빼고 39개를 넣었다.

| 갈래 | 예 | 왜 갈라 두나 |
| --- | --- | --- |
| 구조를 가정하는 것 | IA3 · VeRA · LoHa · LoKr · OFT · TinyLoRA | 층의 모양을 전제하므로 **안 붙을 확률이 높다** |
| 처음 보는 것 | DeLoRA · RandLoRA · GraLoRA · UniLoRA · Peanut | 붙는지 자체가 정보다 |
| 프롬프트 계열 | Prompt Tuning · P-Tuning · Prefix Tuning · CPT | 어댑터가 아니라 **가상 토큰**을 앞에 붙인다 |

**터지는 것도 결과다.** 무엇이 KORMo에 못 붙는지를 그리는 것이 목적이므로, 실패는 버리는
값이 아니라 기록할 값이다. 다만 **"인자를 잘못 준 것"과 "진짜 안 붙는 것"은 다르므로**,
`sweep.py --check`로 GPU를 쓰기 전에 설정 단계에서 한 번 거른다. 실제로 `oft`가 여기서
걸렸는데 호환성 문제가 아니라 인자를 둘 다 준 실수였다.

## 2. LoRA 변형 3개 · rank 4개 · 학습률 3개

LoRA가 붙는 것은 확인됐으므로, 그 위에서 흔든다.

| 무엇 | 값 | |
| --- | --- | --- |
| 변형 | DoRA · rsLoRA · PiSSA | `peft` 플래그 하나라 값이 거의 안 든다 |
| rank | 8 · 16 · 64 · 128 | 기준은 32 |
| 학습률 | 5e-5 · 1e-4 · 5e-4 | 기준은 2e-4 |

**학습률이 특히 중요해졌다.** 기준 조건이 붕괴(37건 전부 negative)했는데, 학습률이 높아
극단으로 간 것인지 데이터 탓인지를 이 3개가 가른다. 자세한 것은
`docs/베이스라인_기록.md`에 있다.

## 3. 구조화 조건 5개 · 교차 2개

기획서 3.3의 축 1(무엇을 학습시키나)과 축 2(데이터 구성)가 요구하는 비교다.

| 설정 | 바꾸는 칸 | 확인할 것 |
| --- | --- | --- |
| `lora-full-bare` | `rules: false` | 규칙서 3,300자를 붙이는 것이 도움이 되나 |
| `lora-noimpacts-rules` | `target: no-impacts` | 중간 산출물인 `impacts` 배열이 필요한가 |
| `lora-sentence-rules` | `target: sentence` | 최종 문장만 학습시켜도 되나 |
| `lora-full-nonegative` | `negatives: drop` | negative를 빼면 과대해석이 느나 |
| `lora-full-down120` | `downsample: 120` | 한 계열 쏠림(60%)이 결과를 가리나 |

**교차 2개**(`lora-noimpacts-bare`·`lora-sentence-bare`)는 구조화 조건과 규칙서 조건을
동시에 바꾼 것이다. 한 축씩만 흔들면 두 조건이 서로 영향을 주는지를 못 본다.

**`sentence` 조건은 채점에서 유리하다.** `labels`를 아예 안 내므로 AM2(어휘 준수)와
AM3(중복 없음)이 검사할 것이 없어 두 항목이 자동으로 1점이 된다. 축 1을 나란히 놓을 때
이것을 감안해야 한다.

## 4. seed 12개

주요 6조건(기준 + 위 구조화 5개)에 seed 43·44를 더한 것이다. seed는 가중치 초기화와
데이터 순서를 정하는 난수의 출발점이라, 바꾸면 같은 설정도 결과가 조금 달라진다.

**홀드아웃이 37건이라 한 건이 2.7%p다.** 두 조건이 10%p 차이 나도 그것이 진짜 차이인지
흔들림인지 seed 하나로는 말할 수 없다. 기획서가 결론을 요구하는 축 1·2에만 seed를 붙인
이유가 이것이다 -- PEFT 방법론 39개는 "붙나 안 붙나"가 사실상 예·아니오라 seed가 필요 없다.

## 이 문서를 고쳐야 할 때

- `configs/`에 설정을 더하거나 뺐을 때
- `_base.json`의 기준값을 바꿨을 때 (그러면 68개 전부의 뜻이 바뀐다)
- `--check`에서 떨어진 것을 살리거나 포기했을 때
