# 1차 스윕 결과 (2026-08-12)

표 원본은 `runs/sweep.md`에 있다. 조합이 어떻게 나왔는지는 `docs/스윕_구성.md`,
학습 전 값은 `docs/베이스라인_기록.md`에 있다.

**설계한 것은 68개인데 돌린 것은 70개다.** DeLoRA가 첫 판에서 유일하게 붕괴를 벗어나
seed 43·44를 뒤늦게 붙였기 때문이다. `docs/스윕_구성.md`의 68은 설계 시점 숫자이고,
여기 70은 실제로 돌린 숫자다.

## 한 눈에

```
설정            70개  configs 68 + delora seed 2. 여기에 기준 조건(_base)이 따로 붙는다
표에 오른 것     70줄  설정 69 + 기준 조건 1 (adamss는 --check에서 떨어져 행이 없다)

  결과 나온 것   60개
    됨          11개  <- 이 중 둘은 아래 이유로 사실상 붕괴다
    이상함        6개
    붕괴         43개  (결과가 나온 것의 72%)
  못 돌림        10개  학습이 시작조차 안 됨
```

**붕괴** = 홀드아웃 37건에 판정을 한 종류만 낸 것. AM 점수와 무관하게 실패다.

**`됨` 11개 중 실제로 쓸 만한 것은 9개다.** `lora-pissa`(쏠림 94.6% · 교사일치 35.1%)와
`waveft`(쏠림 97.2% · 교사일치 27.0%)는 반대쪽 판정을 한두 건 흘린 덕에 붕괴 검사를
통과했을 뿐이다. 7절에 자세히 적었다.

**실패도 세 갈래로 갈린다.** 어디서 죽었는지가 곧 그 방법에 대한 정보다.

| | 어디서 | 표에 |
| --- | --- | --- |
| `--check` 탈락 | `peft`가 설정을 아예 안 만듦 | 행 없음 (`adamss` 1개) |
| `못 돌림` | 설정은 됐는데 학습이 죽음 | 행 있음, 점수 없음 (10개) |
| `붕괴` | 학습은 끝났는데 한 판정만 냄 | 행 있음, 점수 있음 (43개) |

## 1. DeLoRA가 유일하게 세 판 다 살아남았다

| | 교사일치 | 맞힌 수 | 쏠림 | AM 평균 |
| --- | ---: | ---: | ---: | ---: |
| delora (seed 42) | 91.9% | 34/37 | 67.6% | 98.4% |
| delora-s44 | 89.2% | 33/37 | 64.9% | 98.9% |
| delora-s43 | 81.1% | 30/37 | 56.8% | 99.5% |

- **실제 수준은 87.4%** (97/111). 91.9%는 세 판 중 상단값이었다.
- 흔들림 폭 4건. 홀드아웃이 37건이라 1건이 2.7%p다.
- 돌리기 전 세운 85% 선을 s43이 밑돌았다(81.1%). **선을 옮기지 않고 그대로 적어 둔다.**
- 그래도 비교 대상(무조건 negative 29.7% · 무조건 positive 70.3%)보다 한참 위다.

**왜 되는지는 가설 단계다.** DeLoRA는 어댑터가 원본 가중치를 미는 힘을 방향과 크기로
나눠 크기를 묶어둔다. 한 방향으로 폭주하는 것을 구조가 막는 셈이라 함정을 피했을 수
있다. 확인된 사실이 아니다.

## 2. 하이퍼파라미터를 흔들어도 결과가 소수점까지 같았다

**표에 완전히 동일한 줄이 21개 있다.** AM 다섯 항목 100%, 교사일치 29.7%,
판정 `{'negative': 37}`.

```
학습률   5e-5 · 1e-4 · 2e-4 · 5e-4          10배 범위
rank    8 · 16 · 32 · 64 · 128             16배 범위
방법     DoRA · OFT · BEFT · DEFT · GLoRA · GRALoRA · LILY · PEANUT · P-Tuning
```

**학습률을 10배 흔들어도 같은 답이 나온다.** 조정을 잘못한 것이 아니라는 뜻이다.

**함정은 데이터가 팠다.** 학습 562건 중 258건(46%)이 negative이고, negative 정답은
23토큰으로 제일 짧다. 손실을 제일 빨리 줄이는 길이 "무조건 negative"라, 경사하강법은
학습률이 빠르든 느리든 거기로 간다.

**그런데 몇몇은 빠져나온다.** 그러므로 결론은 둘 중 하나가 아니라 둘 다다.

- 함정을 판 것은 데이터
- 빠져나오는 것은 방법 (DeLoRA · `sentence` 조건 · MISS)

## 3. 규칙서는 필수다 (축 1)

| 정답 범위 | 규칙서 붙임 | 규칙서 없음 |
| --- | --- | --- |
| `sentence` | 75.7 · 78.4 · 86.5% (세 판 다 탈출) | 29.7% 붕괴 |
| `full` | 29.7% 붕괴 | **10.8%, 37건 중 26건이 파싱 실패** |
| `no-impacts` | 27.0 · 51.4% | 29.7% 붕괴 |

**규칙서를 떼면 JSON 형식조차 못 낸다.** 3,300자를 붙이는 값을 한다.

## 4. `sentence`가 `full`을 이겼다 (축 1)

| 정답 범위 | 교사일치 (seed 42 · 43 · 44) |
| --- | --- |
| `sentence` | 78.4 · 75.7 · 86.5% |
| `no-impacts` | 27.0(붕괴) · 51.4% |
| `full` (기준) | 29.7(붕괴) · 29.7(붕괴) · 56.8% |

**중간 산출물을 빼는 쪽이 나았다.** `impacts`를 먼저 쓰게 하는 설계(Distilling
Step-by-Step)가 이 데이터·이 모델에서는 오히려 붕괴를 도왔다.

**단, AM 점수로 비교하면 안 된다.** `sentence`는 `labels`를 아예 안 내므로 AM2(어휘
준수)·AM3(중복 없음)이 검사할 것이 없어 자동 만점이다. 게다가 AM8s는 "positive인데
주체 목록이 비면 0점"이라, **맞게 positive를 낼 때마다 감점된다** -- 45.9%가 그 값이다
(37 - positive 20 = 17건). 축 1 비교에서 AM8s는 빼야 한다.

## 5. negative를 빼는 것은 해법이 아니다 (축 2)

돌리기 전에 "전부 붕괴하면 negative 비율을 손대자"고 적어 두었던 그 수정이다.
**이미 돌렸고 실패했다.**

```
lora-full-nonegative      70.3%  {'': 1, 'positive': 36}
lora-full-nonegative-s43  59.5%  {'': 5, 'positive': 32}
lora-full-nonegative-s44  70.3%  {'positive': 37}
```

**반대쪽으로 붕괴했을 뿐이다.** 70.3%는 무조건 positive의 점수다(26/37). 비율을
손대는 것은 함정을 옮기는 것이지 없애는 것이 아니다.

계열 쏠림을 줄인 `lora-full-down120`도 51.4 · 49.8 · 16.2%로 나빴다. 학습량이 줄어
형식조차 못 배웠다(파싱 실패 18~31건).

## 6. 정답키 없는 채점만으로는 아무것도 못 가린다

**표를 AM 평균순으로 정렬하면 1등부터 21등까지가 전부 만점 붕괴다.**

`쏠림` 열을 안 붙였다면 이 표는 "21개 방법이 완벽하게 성공"으로 읽혔을 것이다.
게으른 답 하나가 다섯 항목을 전부 만족시키기 때문이다.

```json
{"judgement":"negative","labels":[],"impacts":[],"direct_impact":""}
```

`labels`가 비면 AM2·AM3은 검사할 것이 없어 자동 1점, AM6s는 negative에 배열이
비었으니 자기일관, AM8s는 흘릴 주체가 없다. **AM 다섯 항목 만점이다.**

**이것 자체가 이 스윕의 산출물이다.** 정답키 없는 채점(blind metric)이 게으른 답에
만점을 준다는 것을 60개 실험으로 보였다. 교사 판정과의 일치를 옆에 세우지 않으면
알아챌 방법이 없다.

## 7. 채점기 구멍 (고침)

`scoring.collapsed`가 파싱 실패(`""`)를 판정 한 종류로 세는 바람에
`{'': 1, 'negative': 36}`이 "두 종류"가 되어 검사를 빠져나갔다. **20개가 잘못된
판정을 받고 있었고**, 그중 여섯은 `됨`이었다.

빈 문자열은 모델이 내린 판정이 아니라 JSON을 못 읽었다는 표시다. **기준을 낮춘 것이
아니라 원래 뜻대로 되돌린 것이고, `verdict`의 문턱(평균 60% · 최저 30%)은 손대지
않았다.**

다시 학습하지 않았다. `run/evaluate.py`가 건별 기록을 `eval/records.jsonl`에 남겨 두어
`run.rescore`가 저장된 것만 읽어 다시 매겼다.

`쏠림`(제일 많이 낸 판정의 몫)을 표에 세웠다. **예·아니오 검사로는 "거의 붕괴"를
못 잡기 때문이다.**

| | 판정 | 쏠림 | 교사일치 | 판정 분포 |
| --- | --- | ---: | ---: | --- |
| `waveft` | 됨 | 97.2% | 27.0% | `{'': 1, 'positive': 1, 'negative': 35}` |
| `lora-pissa` | 됨 | 94.6% | 35.1% | `{'negative': 35, 'positive': 2}` |

**둘 다 `됨`인데 무조건 negative(29.7%)만도 못하다.** `waveft`의 27.0%는 10/37이다.
반대쪽 판정을 한두 건 흘린 것만으로 "판정이 한 종류뿐"을 벗어났을 뿐, 실제로는 붕괴다.

**그렇다고 `쏠림`에 문턱을 세우지는 않는다.** 결과를 보고 기준을 만들면 라운드끼리
비교가 끊긴다(`verdict`의 금기와 같은 이유). **숫자만 세워 두고 판정은 사람이 한다** --
읽는 규칙은 이렇다.

```
쏠림 90% 이상   판정이 무엇이든 붕괴로 읽는다. 지금 두 건이라 예외가 아니라 유형이다
교사일치 29.7%  무조건 negative의 점수 (11/37)
교사일치 70.3%  무조건 positive의 점수 (26/37)
```

## 8. KORMo에 안 붙는 것 11개

**학습이 죽은 것 10개** (`못 돌림` -- 설정은 만들어졌는데 학습 중에 터졌다)

```
boft · cartridge · cpt · frod · ln-tuning · osf · poly · prefix-tuning · randlora · trainable-tokens
```

**설정 단계에서 걸린 것 1개** (`adamss` -- `peft`가 설정 객체를 아예 못 만들었다)

`--check`에서 떨어진 것은 큐에 들어가지도 않아 **표에 행이 없다.** 세다가 빠뜨리기
쉬우므로 여기 따로 적어 둔다. scikit-learn을 깔아 한 번 살렸던 설정인데 여전히 걸린다.

**아직 "인자를 잘못 준 것"과 "진짜 안 붙는 것"을 안 갈랐다.** `못 돌림` 쪽은
`runs/<이름>.log` 끝 몇 줄로, `adamss`는 `run.sweep --check --configs configs/adamss.json`
한 줄로 갈린다. 이것을 가르는 것이 기획서가 요구하는 호환성 지도의 나머지 절반이다.

## 9. 다음 스윕에 반영할 것

- **시간 상한이 필요하다.** `hra` 766분(12.8시간) · `fourierft` 701분 · `waveft`
  178분이 18시간의 대부분을 먹고 **셋 다 붕괴했다.** 셋을 뺐으면 나머지가 두 배 더
  돌았다. 오래 끄는 것과 못 배우는 것이 겹치는 이유는 분명하다 -- 못 배운 모델은
  멈추는 법도 못 배워서 매 건이 생성 상한(768토큰)까지 간다.
- **`run.sweep --all`을 결과가 있는 상태에서 부르면 안 된다.** `summary.json`이 없는
  설정을 아직 안 돌린 것으로 보고 다시 학습시킨다. `못 돌림` 10개가 전부 다시 돈다.
- **기준 조건에 설정 파일이 없다.** `_base.json`이 곧 기준 조건이라 `configs/`에
  `lora-full-rules.json`이 없고, 그래서 표에서 그 줄만 PEFT 이름과 소요 시간이 `-`다.

- **총 에폭 수가 다르면 같은 에폭 체크포인트끼리도 비교할 수 없다.** `run/train.py`가
  `lr_scheduler_type`을 안 정해 HuggingFace 기본값 `linear`가 걸리는데, 이것은 학습률을
  시작값에서 0까지 **전체 학습 길이에 걸쳐** 직선으로 떨어뜨린다.

  ```
  3에폭 학습의 3에폭 지점 = 끝    -> 학습률 거의 0
  6에폭 학습의 3에폭 지점 = 중간  -> 학습률 1e-4 부근
  ```

  **그래서 6에폭 학습의 3에폭 체크포인트는 3에폭 학습의 결과가 아니다.** 에폭을 늘린
  실험을 옛 표에 그냥 끼워 넣으면 안 되고, 늘린 것들끼리만 나란히 놓는다.
