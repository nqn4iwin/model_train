# 서버와 학습 환경

2026-08-11에 `ad-068`에서 확인하고 2026-08-12에 전용 venv로 옮기며 고쳤다.
**판본이 바뀌면 이 문서부터 다시 확인한다.**

## GPU

H100 80GB 8장을 여럿이 나눠 쓴다. **이 프로젝트 몫은 4·5번**이다.

측정 당시 0·1번은 남이 75GB씩, 2·6·7번도 사용 중이었다. **`CUDA_VISIBLE_DEVICES`를
지정하지 않으면 0번을 잡아 남의 실험 위에 얹힌다.** `run.train`과 `run.evaluate` 둘 다
미지정이면 실행을 거부하도록 막아 두었다.

10B를 bf16으로 올리면 20GB 정도고 LoRA는 원본을 얼려두므로 **한 장에 넉넉하다.**
짧은 실험 스무 개에 2장을 묶는 것(DDP)은 통신 비용만 붙으므로, 한 장씩 두 개를 나란히
돌린다.

```bash
CUDA_VISIBLE_DEVICES=4 python -m run.train --config configs/a.json &
CUDA_VISIBLE_DEVICES=5 python -m run.train --config configs/b.json &
```

## 판본

**2026-08-12에 `model_train` 전용 venv를 팠다.** 그전에는 `continuous-training/.venv`를
함께 썼는데, 모니터링(W&B)을 붙이려면 `wandb`를 설치해야 하고 그것이 남의 환경을
건드리는 일이라 갈랐다. 아래 "전용 venv" 절에 옮긴 방법이 있다.

```bash
cd /data1/yblee/repository/model_train && source .venv/bin/activate
```

**안 켜면 시스템 파이썬(`/usr/lib/python3`)이 잡혀 `No module named 'torch'`가 난다.**
`run/sweep.py`가 `sys.executable`로 자식을 띄우므로 한 번 켜두면 스윕이 띄우는
학습·채점도 전부 이 venv를 쓴다.

Python 3.10. 패키지 88개이고 전체 목록은 `requirements-frozen.txt`에 있다.

| | |
| --- | --- |
| torch | 2.13.0+cu130 (CUDA 13.0) |
| transformers | 5.14.1 |
| trl | 1.9.2 |
| peft | 0.20.0 |
| accelerate | 1.14.0 |
| numpy | 2.2.6 |
| wandb | 새로 넣음 (공용 venv에는 없었다) |

**판본은 공용 venv와 한 자리도 다르지 않다.** `pip freeze`로 통째로 떠서 옮겼기
때문이다. 그래서 **2026-08-12까지의 74건과 그 이후 실험을 같은 표에 놓을 수 있다** --
판본이 하나라도 달랐으면 그 표는 다른 라운드가 된다.

### 전용 venv를 판 방법

```bash
# 1. 공용 venv 를 켜고 지금 판본을 통째로 뜬다
source /data1/yblee/repository/continuous-training/.venv/bin/activate
pip freeze > /tmp/frozen.txt
deactivate

# 2. 저장소 안에 만든다 (.gitignore 에 이미 .venv/ 가 있다)
cd /data1/yblee/repository/model_train
python -m venv .venv && source .venv/bin/activate
python -m pip install -U pip
pip install -r /tmp/frozen.txt --extra-index-url https://download.pytorch.org/whl/cu130
pip install wandb
```

**`pip freeze`로 뜨는 것이 핵심이다.** 빈 venv에 `pip install transformers`라고만 적으면
pip이 **오늘 기준 최신판**을 주는데, 아래에 적었듯 이 프로젝트는 판본을 올리면 안 된다.

**`--extra-index-url`도 빼면 안 된다.** `torch 2.13.0+cu130`의 `+cu130`은 PyPI가 아니라
PyTorch 자체 저장소에서 온 표시라, 주소를 안 주면 CPU용이 깔린다. 확인은
`torch.cuda.is_available()`이 `True`인지로 한다 -- **CPU용이 깔려도 설치는 성공하고
학습을 시작해야 알아채는 종류의 사고다.**

`pip freeze`가 `이름 @ file:///어디` 꼴로 뱉는 항목이 있으면 로컬 경로에서 깐 것이라
새 venv에서 재현이 안 된다. 2026-08-12 시점에는 88개 중 하나도 없었다.

**transformers 5.x와 KORMo 원격코드가 완전히 맞지는 않는다.** 매 실행마다 두 가지 경고가
난다.

```
The remote code model ... seems to expect `cache_position`.
This arg has been removed from the Transformers library
```
```
`rope_config_validation` is deprecated and has been removed
```

**지금은 경고일 뿐 생성과 학습에 지장이 없다** -- baseline 37건이 정상적으로 돌았다.
다만 다음 transformers 판올림에서 에러가 될 수 있다고 경고가 직접 말하고 있으므로,
**판본을 올리지 않는다.** 2026-08-12에 전용 venv로 갈랐지만 **판본은 그대로 떠서 옮겼고,
이 금지는 그대로다** -- 이제 `continuous-training`을 안 건드리므로 올리는 것이 기술적으로
쉬워졌을 뿐, KORMo 원격코드가 깨질 위험은 하나도 안 줄었다. 올릴 일이 생기면 74건과
비교가 끊긴다는 것을 먼저 셈한다.

## 모니터링

`configs/_base.json`의 `report_to`가 어디에 기록할지를 정한다. 기본은 텐서보드고
W&B를 같이 켜 두었다.

```json
"report_to": ["tensorboard", "wandb"],
"wandb_project": "model_train"
```

**`wandb`가 안 깔린 환경에서는 경고를 찍고 텐서보드로 물러난다**(`run/train.py`).
설정에 적어 놓고 기록이 안 남는 것이 제일 나쁘므로, 조용히 빼지 않고 로그에 남긴다.

W&B 실험 이름은 설정의 `name`이다. 안 주면 `output_dir`이 이름이 되어 목록이 전부
`runs/`로 시작한다.

`api.wandb.ai`는 이 서버에서 닿는다(2026-08-12 확인). 못 닿는 환경이면
`export WANDB_MODE=offline`으로 로컬에 쌓았다가 `wandb sync`로 올린다.

## KORMo 내부는 표준 이름을 쓴다

`KORMoForCausalLM`이라는 자체 모델 클래스라 `trust_remote_code=True`가 필요하지만,
**안의 Linear 층 이름은 llama 계열과 같다.**

```
q_proj 40 · k_proj 40 · v_proj 40 · o_proj 40
gate_proj 40 · up_proj 40 · down_proj 40 · lm_head 1
```

40층이다. `target_modules`를 표준 이름으로 적어도 헛돌지 않는다. **이것이 확인되지
않았다면 LoRA가 아무 층에도 안 붙은 채 에러 없이 "아무것도 학습 안 된 모델"이 나올 수
있었다** -- 조용히 망하는 종류라 스윕 전에 봐야 했다.

`eos_token`은 `<|EOS|>` (id 125031)이다. TRL이 정답 끝에 자동으로 붙인다
(`Adding EOS to train dataset`). base 모델이 멈추는 법을 배우려면 이것이 필수다.

## 문맥 길이 -- 창의 2%만 쓴다 (2026-08-12 전수 확인)

| | |
| --- | --- |
| KORMo 컨텍스트 윈도우 | **131,072토큰** (`config.json`의 `max_position_embeddings`) |
| 설정에 건 상한 `max_length` | 4,096토큰 |
| 가장 긴 입력 (599건 중) | 5,893자 ≈ **2,768토큰** |
| 평균 | 3,830자 ≈ 1,800토큰 |

**글자 수와 토큰 수를 헷갈리지 않는다.** 이 데이터는 **글자당 0.470토큰**이다
(`--inspect`가 첫 건을 3,504자 = 1,646토큰으로 세어준 데서 나온 비율). 규칙서가
3,393자라 입력이 길어 보이지만 토큰으로는 절반도 안 된다.

**실제로 조심할 것은 모델 창이 아니라 우리가 건 4,096이다.** 넘으면 TRL이 뒤를
잘라내는데 잘리는 것이 **정답 끝**이라, 에러 없이 학습만 조용히 망가진다. 거기에도
1,328토큰(32%)이 남는다.

**68개 설정 전부에 대해 말할 수 있다.** 길이를 바꾸는 칸은 `rules`와 `target` 둘뿐이고,
`max_length`를 건드린 설정 파일은 하나도 없다. 두 칸은 전부 기준값보다 **짧아지는
쪽으로만** 바뀐다.

```
규칙서+full (기준)   최대 5,893자   <- 가장 긴 조건. 562건 전부 상한 통과
규칙서+sentence      최대 4,406자
규칙서없음+full       최대 2,617자
```

기준 조건이 두 축 모두에서 최대이므로, 나머지 67개는 볼 것 없이 짧다.

**여유가 이만큼이라 프롬프트에 예시를 몇 개 넣는(few-shot) 실험을 붙일 자리는 얼마든지
있다.**

## peft가 지원하는 42종

**흔들 후보가 전부 있다.** 사용자가 언급한 `TINYLORA`도 실재한다.

```
ADALORA  ADAMSS  ADAPTION_PROMPT  BEFT  BOFT  C3A  CARTRIDGE  CPT  DEFT
DELORA  FOURIERFT  FROD  GLORA  GRALORA  HIRA  HRA  IA3  LILY  LN_TUNING
LOHA  LOKR  LORA  MISS  MULTITASK_PROMPT_TUNING  OFT  OSF  PEANUT  POLY
PREFIX_TUNING  PROMPT_TUNING  PSOFT  PVERA  P_TUNING  RANDLORA  ROAD
SHIRA  TINYLORA  TRAINABLE_TOKENS  UNILORA  VBLORA  VERA  WAVEFT  XLORA
```

`LoraConfig`에 `use_dora`·`use_rslora`·`init_lora_weights`·`lora_bias`가 모두 있다.
**DoRA와 rsLoRA는 플래그 하나라 값이 거의 안 든다.**

설정 JSON의 `peft.peft_type`에 이름을 적으면 그대로 만들어진다. 목록에 있다는 것이
**KORMo에 붙는다는 뜻은 아니다** -- 구조를 가정하는 방식은 붙다가 터진다. 무엇이 붙고
무엇이 안 붙는지를 알아내는 것이 이 스윕의 목적이므로, **터지는 것도 기록할 결과다.**
